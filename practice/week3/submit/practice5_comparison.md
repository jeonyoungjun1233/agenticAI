# 실습 5 비교 메모

## 문서 규칙만 있을 때

- 사람이 `work-rules.md`를 읽고 직접 지켜야 한다.
- 출력 파일이 빠져도 자동으로 잡아주지 않는다.
- 세션이 바뀌면 같은 규칙을 다시 설명해야 할 수 있다.

## hook을 붙였을 때

- 작업 완료 후 `check_outputs.ps1`가 핵심 출력과 결과 파일 존재 여부를 자동 검사한다.
- 결과 파일이 없으면 실패로 간주할 수 있어 누락을 빨리 발견한다.
- 문서 규칙이 자동 검증 단계로 확장된다.

## memory를 붙였을 때

- `PROJECT_MEMORY.md`에 출력 위치, 검증 절차, 금지 명령을 적어 세션 간 일관성을 높인다.
- 새 작업을 시작할 때도 같은 출력 위치와 같은 검증 절차를 반복 적용하기 쉽다.

## 역할 분담 정리

- Skill / Instruction: 어떻게 일할지 정한다.
- Hook: 작업 뒤에 무엇을 자동 검사할지 정한다.
- Memory: 프로젝트에서 계속 기억할 문맥을 정한다.
- MCP: 실제로 어떤 도구를 호출할 수 있는지 정한다.

## 결론

- 규칙만 있을 때보다 hook과 memory를 함께 두면 자동성, 일관성, 재검토성이 모두 좋아진다.
